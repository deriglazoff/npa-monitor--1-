# npa-monitor

Сбор нормативных документов с трёх официальных порталов РФ за произвольный
период, с отбором по тематическим направлениям и выгрузкой в CSV / XLSX.

Источники: **cbr.ru**, **sozd.duma.gov.ru**, **regulation.gov.ru**.

Статус: **PoC**. Три источника собирают карточки; `regulation.gov.ru` —
через POST-поиск фронтенда, не через заглушку `GET /Projects`.
Ограничения ниже — про полноту текста и периметр, не про пустые поля.

---

## Быстрый старт

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

cp .env.example .env      # если .env ещё нет; в поставке он уже заполнен

# 1. Проверить, что все три источника достижимы
PYTHONPATH=src .venv/bin/python -m npa_monitor doctor

# 2. Собрать документы за период
PYTHONPATH=src .venv/bin/python -m npa_monitor collect \
    --from 29.06.2026 --to 05.07.2026

# 3. То же самое из окна (даты, источники, кнопка «Выгрузить»)
PYTHONPATH=src .venv/bin/python -m npa_monitor gui
```

Результат появится в `out/` двумя файлами: `npa_<период>.csv` и
`npa_<период>.xlsx`.

### Ключи запуска

| Ключ | Назначение |
|---|---|
| `--from` / `--to` | границы периода, формат `ДД.ММ.ГГГГ` (обязательные) |
| `--sources` | подмножество источников: `sozd,cbr,regulation` |
| `--no-filter` | выгрузить всё без тематического отбора |
| `--no-content` | не скачивать содержание документов |
| `--config` | путь к своему `config.yaml` |
| `--out` | каталог для выгрузки |
| `-v` | подробный лог |

## Windows: окно и .exe

Двойной клик по `npa-monitor.exe` открывает окно: период, источники,
кнопки **Проверить источники** и **Выгрузить**. Сбор идёт в фоне, ход
пишется в журнал, результат — CSV и XLSX в выбранную папку (по умолчанию
`out/` рядом с exe).

Можно отдать пользователю **один** `npa-monitor.exe`: темы фильтра, источники
и маршруты (`direct`) уже внутри. Рядом ничего класть не обязательно.

Если рядом с exe есть `config.yaml` или `.env` — берутся они (можно править
без пересборки). Если файлов нет, при первом запуске программа по возможности
положит рядом копии `config.yaml` и `.env.example` — чтобы было чем править.

```powershell
# сборка (нужен Python с tkinter — обычный установщик python.org)
.\scripts\build_exe.ps1
```

Готовый файл: `dist/npa-monitor.exe`. Прокси нужен только вне РФ, и только
для `sozd` — тогда создайте `.env` рядом с exe, см. раздел ниже.

CLI после сборки не входит в exe (окно без консоли). Командная строка
по-прежнему: `python -m npa_monitor collect|doctor`.

## Прокси: зачем и когда он не нужен

`sozd.duma.gov.ru` не принимает соединения из-за пределов РФ — отказ происходит
на транспортном уровне, ещё до HTTP. Поэтому в поставку включён временный
российский прокси.

**Если вы запускаете из России — прокси не нужен.** Встроенные настройки уже
`SOZD_ROUTE=direct`, файл `.env` создавать не обязательно.

**Прокси в поставке временный: он выдан на 3 дня (по 16.08.2026).** После этого
`doctor` покажет сбой на `sozd`. Замените строку `PROXY_URL` в `.env` на свой
российский прокси в том же формате `http://логин:пароль@хост:порт`.

### Маршрут — свойство источника, а не общая настройка

Неочевидное, но важное: **тот же прокси ломает два других источника.**
`cbr.ru` и `regulation.gov.ru` не отвечают через датацентровый российский IP
(они режут такие адреса), хотя напрямую работают. Поэтому маршрут задаётся
отдельно для каждого источника:

```
SOZD_ROUTE=proxy          # только через РФ
CBR_ROUTE=direct          # только напрямую
REGULATION_ROUTE=direct   # только напрямую
```

При запуске изнутри РФ все три можно перевести в `direct`.

## Тематический фильтр

Отбор задаётся в `config.yaml` — пятью направлениями из исходного техзадания:
финансовый сектор, ИТ, информационная безопасность, трудовое законодательство,
охрана труда. Документ попадает в выгрузку, если сработало хотя бы одно
ключевое слово хотя бы из одного направления.

Слова записаны усечёнными основами (`кредитован`, `взыскани`, `отпуск`) —
это покрывает падежи без словаря морфологии. **Чтобы сузить или расширить
охват, правьте только `config.yaml`, код трогать не нужно.**

В выгрузке две служебные колонки показывают, почему документ отобран:
`Направления` и `Сработавшие слова`. По ним видно ложные срабатывания —
если они появятся, лечится уточнением списка слов.

## Колонки выгрузки

`Источник`, `Тип документа`, `Номер`, `Наименование`, `Дата публикации`,
`Дата смены статуса`, `Статус / стадия`, `Ведомство`, `Ссылка на портал`,
`Файл`, `Направления`, `Сработавшие слова`.

Колонка **Ссылка на портал** — URL карточки на сайте источника.
Колонка **Файл** — относительный путь к локальному файлу в папке
`npa_<период>_content/` рядом с CSV/XLSX (в Excel это гиперссылка).
Туда кладутся скачанные docx/pdf/html. Если у карточки нет файла,
ячейка пустая. Пропуск скачивания: `--no-content`.

Про даты у законопроектов: отбор идёт по **наличию события в заданном
периоде**, а в колонке «Дата смены статуса» стоит **последнее известное**
событие по карточке. Оно может быть позже конца периода — это не ошибка:
законопроект попал в выборку за событие внутри недели, но с тех пор успел
продвинуться дальше.

## Что и как собирается

### sozd.duma.gov.ru — работает полностью

Страница поиска `/oz` принимает фильтр диапазона дат в параметре
`b[ExistsEventsDate]` (формат `ДД.ММ.ГГГГ - ДД.ММ.ГГГГ`) и обычную пагинацию
`&page=N` по 10 записей. Весь контент отдаётся сервером — headless-браузер
не нужен. Собираются номер, наименование, стадия рассмотрения, даты, ссылка.

Фильтр дат проверен контролем: три разных периода дают три непересекающихся
диапазона номеров законопроектов, монотонных по времени.

### cbr.ru — работает полностью

Раздел `/news/` не содержит новостей в HTML — они подставляются скриптом.
Реальные источники данных найдены в inline-коде страницы. **Лент две, и они
дополняют друг друга:**

```
GET /news/eventandpress/?page=N&IsEng=false&type=100
    &dateFrom=&dateTo=&Tid=&vol=&phrase=&pagesize=20     # события, пресс-релизы, интервью

GET /news/new_ent/?page=N&IsEng=false
    &dateFrom=&dateTo=&Tid=&phrase=&pagesize=20          # новости и аналитические материалы
```

Сбор только одной ленты даёт пробелы, причём молчаливые: на 13.08.2026 первая
обрывалась на 27.07, вторая содержала материалы по 12.08 — по одной ленте
свежая неделя выглядела бы пустой. Контрольная проверка: неделя 03–09.08.2026
давала 0 записей по одной ленте и 16 по двум.

Три особенности, важные при доработке:

* эндпоинты требуют **весь** набор параметров, включая пустые `Tid`, `vol`,
  `phrase`; при неполном наборе возвращают `{"Error":"Error loading data."}`;
* наборы параметров у лент **различаются**: у `new_ent` нет `type` и `vol`;
* параметры `dateFrom` / `dateTo` **сервером игнорируются** — проверено на
  трёх разных периодах, ответ всегда с текущей ленты. Поэтому период
  применяется на нашей стороне: лента пагинируется вглубь, пока даты не уйдут
  раньше начала периода. Это надёжнее, чем полагаться на их серверный фильтр.

Дополнительно снимается витрина `/project_na/` — проекты нормативных актов,
находящиеся на публичном обсуждении. Для прошедшего периода она обычно пуста
(показывает только текущее окно), но для регулярного режима это основной
источник проектов НПА.

### regulation.gov.ru — работает полностью

Список проектов — `POST /api/public/PublicProjects/GetFiltered` (его вызывает
страница `/projects/?type=ListView`). `GET /api/public/Projects` тоже отвечает
200, но отдаёт только идентификаторы с пустыми полями — этим эндпоинтом
пользоваться нельзя.

Тело запроса:

```
POST /api/public/PublicProjects/GetFiltered
Content-Type: application/json
Referer: https://regulation.gov.ru/

{
  "listParams": {"filterModel": {"filters": "", "page": N, "pageSize": 20}},
  "orderedFields": ["id", "title", "startPublicDiscussion",
                    "endPublicDiscussion", "developedDepartment",
                    "stage", "status", "procedure", ...]
}
```

Ответ содержит наименование, ведомство, стадию, статус и даты. Поле
`publicationDate` часто `null`, `creationDate` — заглушка `0001-01-01`.
Отбор по периоду идёт по **`startPublicDiscussion`** на нашей стороне:
лента пагинируется вглубь, пока даты не уйдут раньше начала периода.

## Ограничения

**1. Отбор по ключевым словам — по заголовку, не по тексту документа.**
Документ, у которого тематика раскрывается только в теле, а в названии её нет,
в выборку не попадёт. Для полноты потребуется скачивание и разбор текстов
(у ЦБ это PDF).

**2. Периметр — три портала из техзадания.** Публикация принятых актов на
`publication.pravo.gov.ru` не охватывается.

## Регулярный мониторинг

PoC собирает срез за период по запросу. Для постоянного режима правильная
схема иная, и это стоит учесть до начала промышленной реализации:

**Снимать срез ежедневно и копить в базе, а «что изменилось за неделю»
считать диффом между срезами** — вместо архивного запроса к порталу.

Причина: динамические фильтры по датам — самая хрупкая часть госпорталов
(у `cbr.ru` серверный фильтр уже не работает, у `regulation.gov.ru` дата
публикации в API пустая — режем по `startPublicDiscussion` сами). При ежедневном
срезе вы от их фильтров не зависите совсем, а
история изменений статусов накапливается у вас и становится точнее, чем то,
что портал показывает на витрине.

Обязательный элемент такого режима — **алерт на нулевой срез**. Портал
переверстают, парсер отдаст пустоту, и без сигнала пробел накопится незаметно.

## Структура проекта

```
npa-monitor/
├── .env                 рабочая конфигурация (прокси, маршруты)
├── .env.example         шаблон для своей конфигурации
├── config.yaml          тематические направления и ключевые слова
├── npa-monitor.spec     сборка Windows .exe
├── requirements.txt
├── requirements-build.txt
├── scripts/build_exe.ps1
├── out/                 выгрузки
└── src/npa_monitor/
    ├── __main__.py      CLI: collect / doctor / gui
    ├── gui.py           окно выгрузки (точка входа .exe)
    ├── runner.py        общий прогон collect / doctor
    ├── paths.py         корень приложения: исходники vs .exe
    ├── http.py          HTTP-слой с маршрутом на источник
    ├── models.py        единая схема документа
    ├── filters.py       тематический отбор
    ├── export.py        CSV / XLSX
    ├── content.py       скачивание содержания рядом с выгрузкой
    └── sources/
        ├── sozd.py
        ├── cbr.py
        └── regulation.py
```

Проект самостоятельный: внешних зависимостей кроме перечисленных в
`requirements.txt` нет, к другим системам не обращается.
